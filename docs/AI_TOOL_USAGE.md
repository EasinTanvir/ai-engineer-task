# AI Tool Usage

I used two AI tools during this project, in distinct roles:

**Claude (Anthropic)** — used as an architecture and design-review partner throughout. I worked through the system design interactively: how to combine RAG with structured-data tools, how to enforce access control at the query layer rather than through model instructions, how to make action confirmation a structural guarantee rather than a prompt suggestion, and how to encode source-authority ranking given the assessment's conflicting-document scenario. I used it to review Codex-generated code file by file, and it surfaced concrete issues I then decided how to address — including a customer-facing response that mislabeled account data, a missing error handler on the database connection pool, and a schema gap (`NOT NULL` fault fields) that would have broken ingestion on a plausible new test record. All architectural and product decisions — what to build, what to defer, and how to prioritize the two additional client problems — were mine; the tool served as a design sounding board and code reviewer, not a decision-maker.

**OpenAI Codex** — used for implementation, driven by a staged, written specification I authored (`AGENTS.md` plus a sequence of scoped prompt files, one per build stage: data migration, agent/tools, UI, proactive detection, and a targeted bug fix). Each stage had explicit acceptance criteria drawn from the real source data before implementation began, and each was manually verified against those criteria — including adversarial checks I ran myself (e.g. attempting cross-account access directly rather than trusting a self-reported pass) — before moving to the next stage. This staged approach was a deliberate choice to keep the AI-generated code auditable and scoped, rather than generating the whole system in one pass and hoping it held together.

In short: the tools accelerated implementation and helped catch real bugs, but the system design, the trade-offs, the testing strategy, and every decision about what shipped were mine.
