# Prompt: Chat UI

## Goal

A minimal, functional Next.js chat interface on top of the working `/api/chat` endpoint. No visual polish required — clarity over aesthetics.

## Prerequisite

Stage 2 (`prompts/02-agent-and-tools.md`) is complete and all 6 acceptance cases pass.

## Requirements

- **Account switcher**: a simple dropdown/selector for the 4 mocked accounts (ACCT-001..004), used to set the session `accountId` the API route reads. Switching accounts should clear/reset the conversation.
- **Chat panel**: message list (user/assistant distinction), input box, send button, basic loading state while awaiting a response.
- **Tool trace display**: for each assistant turn, show which tool(s) were called and with what result — a simple collapsible list under the message is enough (e.g. "🔧 search_policy_docs → 3 results", "🔧 lookup_order → ORD-1001"). Use the `toolCalls` array already returned by `/api/chat`.
- **Confirmation turns**: when the assistant's reply includes a pending escalation proposal, make this visually distinct (e.g. a highlighted box) so it's clear a "yes" from the user will trigger a real action — plain text confirmation is fine per AGENTS.md; no separate confirm button required.
- Handle empty state (no messages yet) and basic error state (API failure) — nothing elaborate.

## What NOT to do

- No auth beyond the mocked account selector.
- No proactive detection dashboard (stage 4).
- No styling framework decisions beyond whatever is already in the project — keep it plain.

## Acceptance Criteria

- Can switch between all 4 accounts and get correctly-scoped answers.
- Every assistant message visibly shows which tool(s) it used.
- The full escalation flow (propose → visually distinct confirmation prompt → confirm → success message) is demonstrable end-to-end in the UI.

## Report back

A short description of the component structure, plus confirmation that the 4 acceptance criteria above were manually tested.
